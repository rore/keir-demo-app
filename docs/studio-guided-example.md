# Show Maya what her customization does

[Walk through the clickable design](studio-guided-example.html). The standalone preview uses illustrative outcomes throughout, including the final task check. It can be opened directly without starting a service. The production handoff below identifies where real saved results must replace the illustration.

Design proposal for the customer Studio. The example changes the advice Maya sees when she checks a saved task. The task itself stays open or completed. The conversation is scripted and works without an AI connection. Sample checks, approval, turning the change on and checking a real task use Daymark's existing behavior.

## Where the current journey loses Maya

- **The opening lacks an object.** “In use · Pending” can sound as if setup is waiting. “When you check an open task, what should it say?” gives Maya no task to look at. On the seeded account, Pending is the actual advice returned for an open task. Show that relationship in the first exchange.
- **The app asks Maya to orchestrate the check.** In Maya’s reported session, both current and proposed advice said Pending. The same screen offered multiple review buttons and repeated the question after a successful check. The current app still puts proposal, sample and management actions in a toolbar and opens results as a table of checks. Carry one task and its advice through the conversation. If the desired wording already applies, say so and offer to check it on a task. Keep older runs reachable under history.
- **An invitation leads to an unavailable action.** With no assistant configured, Maya can type an answer to the opening question but cannot send it. Setup and connection status take space that could explain the example. Offer a usable example right there and keep setup beside the separate action for writing a personal request.
- **The last mile is missing.** Approval, turning on the change and seeing its effect happen in different places. End at the native task's existing **Check task advice** control. Only the native check can show what happened on that saved task.

## One example, inside Studio

**Entry.** Under **New customization**, show one invitation: **Try an example — change the advice on an open task.** Add “A guided example. No AI connection needed.” Also offer the same link when Maya opens her existing task advice. Keep **Write my own request** as a separate route with the existing connection status and Configure action when needed. Opening the example only reads current state. Never present scripted lines as generated replies, prefill the real composer, or send its draft. While inside the example, use the small persistent label **Guided example** and an **Exit example** link.

**Treatment.** Keep the ordinary Daymark shell and its typography. Use conversation for a short exchange and a single leading action in the latest turn. Differentiate the canvas by using the native task layout, task status and a clearly labeled advice line. Avoid a second stream of chat bubbles. On wide screens keep the draggable divider. On phones show the sample as one focused view with **Back to conversation** returning to its invoking turn. Keep the sample heading and the current decision reachable on short screens. History, recovery and technical details belong behind one quiet entry.

**Resume and exceptions.** Starting an example cannot replace an unrelated saved draft. Let Maya resume it, or inspect the illustrative sample without saving over it. When the same example is already approved or active, lead with the true saved state and the relevant next action. Reopening an old result must show the original expected and observed values. A mismatch identifies the expected and observed advice and offers **See the difference**. A failed or stale check keeps activation unavailable and offers a fresh check of the current proposal. On uncertain approval or activation, read back the saved state before offering another action. Switching people clears the prior person's conversation and results.

## Acceptance walkthrough

Use a disposable seeded Maya with AI unconfigured. Start at **New customization**. Before taking any action, a reader should be able to say what the example changes and how to try it. Follow the example using only its visible replies. At the sample, identify the task status, today's advice and proposed advice. At review, find the actual open and completed examples and inspect the remaining cases. Approve, leave and return. Verify the old advice is still in use. Turn on the change, return to a saved open task and use **Check task advice**. Verify the advice changes and the task itself does not. Check that another person's advice and Maya's unsent personal request survive separately.

Repeat the decision points with keyboard navigation and at phone width. Open an older run and a mismatching or unavailable result. Neither can turn on the proposed change. Verify that the guided path made no AI calls. This is a first-party walkthrough for the proposed implementation. It does not establish that business users have tested it.
